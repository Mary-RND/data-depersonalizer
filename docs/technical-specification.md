# Техническое задание на MVP: локальное приложение деперсонализации данных

> Исходный документ курсового проекта (Lesson 3). Воспроизведён без изменений.

## 1. Паспорт документа

- Проект: «Деперсонализатор» — локальное приложение деперсонализации табличных данных
- Заказчик: внутренняя задача курса (работа с данными клиентов)
- Версия: 1.0
- Дата: 28.08.2026
- Статус: согласовано

## 2. Контекст и проблема

Пользователь работает с таблицами Excel (xlsx), содержащими персональные данные (ФИО, телефоны, email, адреса и прочие чувствительные значения). Для передачи таких данных аналитикам, подрядчикам или в учебные/тестовые сценарии их нельзя отдавать в исходном виде. Сейчас пользователь редактирует файлы вручную: стирает или придумывает значения, что занимает время, приводит к расхождениям и делает невозможным обратное восстановление, когда данные нужны снова.

Бизнес-последствие: риск утечки персональных данных и лишние трудозатраты на ручную обработку и восстановление. Решение — локальный инструмент, который автоматически заменяет выбранные значения на индексы, сохраняет «словарь» соответствий и умеет выполнять обратную конвертацию.

## 3. Цель и метрики успеха

- Цель: автоматизировать деперсонализацию xlsx-таблиц с заменой выбранных колонок на индексы, хранением ключевой таблицы и обратным восстановлением исходных значений.
- Метрика 1: 100% уникальных значений в выбранных колонках заменены на индексы, ни одно исходное значение не попало в выходной файл.
- Метрика 2: обратная конвертация восстанавливает 100% исходных значений без ручных правок.
- Метрика 3: полный цикл «прямая → обратная конвертация» занимает не более 2 минут на тестовом файле с 1 000 строк.

## 4. Пользователи

| Роль | Задача | Права/ограничения |
|---|---|---|
| Пользователь данных | Загрузить xlsx, отметить чувствительные колонки, получить деперсонализированный файл и ключ | Локальный доступ, без записи в базы и сеть |
| Владелец ключа | Выполнить обратную конвертацию по паре файлов | Может восстановить данные только при наличии ключа |

## 5. Границы MVP

### Входит

- Загрузка xlsx-файла (первый лист) и вывод списка колонок.
- Выбор пользователем колонок, значения которых заменяются на индексы.
- Генерация индексов формата `ИД<номер колонки>_<порядковый номер>` (например, `ИД1_0001`).
- Сохранение двух файлов: деперсонализированная таблица и ключевая таблица-словарь.
- Диалог выбора пути сохранения (стандартный диалог «Сохранить как») — пользователь явно указывает, куда сохранить таблицы.
- Обратная конвертация: восстановление исходных значений по паре «деперсонализированный файл + ключ».
- Запрос пути сохранения результата обратной конвертации.
- Понятные сообщения об ошибках и подтверждениях на русском языке.

### Не входит

- Выход в интернет, сетевые запросы, облачные сервисы.
- Использование нейросетей, ML-моделей и любых внешних вычислительных сервисов.
- Шифрование файлов и парольная защита (ключ хранится как обычный xlsx).
- Обработка форматов, отличных от xlsx (csv, xls, ods и др.).
- Многостраничные книги Excel — обрабатывается только первый лист.
- Авторизация, журналирование действий, аналитика и телеметрия.
- Пакетная обработка нескольких файлов за один запуск.
- Встроенный просмотр данных (таблица не отображается, только список колонок и выбор).

## 6. Основной сценарий (прямая конвертация)

1. Пользователь открывает приложение и нажимает «Загрузить файл».
2. Выбирает исходный xlsx; приложение читает первый лист и показывает список колонок с отмеченными чекбоксами.
3. Пользователь отмечает чувствительные колонки и жмёт «Деперсонализировать».
4. Приложение показывает сводку: список выбранных колонок и количество уникальных значений, которые будут заменены.
5. Пользователь подтверждает; приложение запрашивает, куда сохранить деперсонализированный файл (`..._деперсонализированные.xlsx`).
6. После выбора пути приложение запрашивает, куда сохранить ключ (`..._ключ.xlsx`).
7. Приложение выполняет замену, сохраняет оба файла и показывает сообщение об успехе с путями.

### Вспомогательный сценарий (обратная конвертация)

1. Пользователь нажимает «Обратная конвертация».
2. Указывает деперсонализированный xlsx и файл ключа.
3. Приложение запрашивает, куда сохранить восстановленный файл (`..._восстановлено.xlsx`).
4. Приложение восстанавливает исходные значения и показывает сообщение об успехе.

### 6.1 Сценарий Word (.docx)

Прямая конвертация:

1. Пользователь нажимает «Прямая конвертация (Word)» и выбирает исходный .docx.
2. В окне отмечает категории «Телефоны», «Email», «ФИО» и при необходимости вводит собственные значения (по одному на строку).
3. Подтверждает сводку (выбранные категории и количество дополнительных значений).
4. Указывает путь сохранения деперсонализированного документа (по умолчанию `*_деперсонализированные.docx`), затем путь сохранения ключа (по умолчанию `*_ключ.docx.xlsx`).
5. Приложение находит персональные данные по правилам (телефоны не менее чем с 10 цифрами, стандартные email-адреса, консервативный шаблон ФИО из 2-4 слов с заглавной буквы), заменяет уникальные значения на индексы `ИДТЕЛ_NNNN`, `ИДЕМЕЙЛ_NNNN`, `ИДФИО_NNNN`, `ИДДОП_NNNN`, сохраняет оба файла и показывает сообщение об успехе с путями и предупреждением о хранении ключа.

Обратная конвертация:

1. Пользователь нажимает «Обратная конвертация (Word)».
2. Указывает деперсонализированный .docx и файл ключа.
3. Приложение запрашивает, куда сохранить восстановленный документ (`*_восстановлено.docx`).
4. Приложение заменяет индексы на исходные значения и показывает сообщение об успехе.

Замечание MVP: замена выполняется на уровне абзаца; форматирование текста рядом с заменённым фрагментом (жирный, шрифт, размер) может не сохраниться — документ остаётся корректным и открывается в Word.

## 7. Функциональные требования

| ID | Требование | Приоритет | Критерий приемки |
|---|---|---|---|
| FR-01 | Загрузка xlsx-файла и отображение набора колонок первого листа | Must | После выбора файла пользователь видит список колонок |
| FR-02 | Выбор колонок для деперсонализации через чекбоксы | Must | Отмеченные колонки попадают в сводку |
| FR-03 | Замена значений выбранных колонок на индексы формата `ИД<N>_<NNNN>` | Must | В выходном файле выбранные ячейки содержат только индексы |
| FR-04 | Одинаковые исходные значения в одной колонке получают один и тот же индекс | Must | Для файла-теста повторяющееся значение маппится на один индекс |
| FR-05 | Пустые ячейки не заменяются и не попадают в ключ | Must | Пустые ячейки остаются пустыми, в ключе отсутствуют |
| FR-06 | Сохранение деперсонализированного xlsx с подтверждением пути | Must | Открывается диалог «Сохранить как»; без выбора пути сохранение не выполняется |
| FR-07 | Сохранение ключевой таблицы-словаря (колонки: Исходная_колонка, Индекс, Исходное_значение) | Must | Ключ содержит все заменённые значения и корректно читается обратным сценарием |
| FR-08 | Обратная конвертация по паре «файл + ключ» | Must | Восстановленный файл совпадает с исходным по выбранным колонкам на 100% |
| FR-09 | Запрос пути сохранения результата обратной конвертации | Must | Диалог сохранения появляется до записи файла |
| FR-10 | Валидация выбора: минимум одна колонка должна быть отмечена | Must | Без отмеченных колонок кнопка «Деперсонализировать» недоступна или выводится ошибка |
| FR-11 | Проверка совместимости ключа с файлом при обратной конвертации | Should | При несовпадении структуры — ошибка с объяснением, файл не создаётся |
| FR-12 | Исходный файл не изменяется | Must | После операции исходный xlsx остаётся без изменений (проверка по контрольным суммам) |
| FR-13 | Деперсонализация .docx: поиск и замена категорий «Телефоны», «Email», «ФИО» по встроенным правилам | Must | Уникальные значения выбранных категорий заменены на индексы `ИДТЕЛ_`, `ИДЕМЕЙЛ_`, `ИДФИО_`; документ остаётся корректным .docx и открывается в Word |
| FR-14 | Дополнительные пользовательские значения (произвольные строки, по одной на строку) | Must | Каждое введённое непустое значение заменяется на индекс `ИДДОП_` и попадает в ключ; пустые строки игнорируются |
| FR-15 | Замена выполняется по всему документу: тело, таблицы, колонтитулы; одинаковые значения получают один индекс | Must | Один и тот же телефон в тексте и в таблице маппится на один индекс; ключ содержит все уникальные значения |
| FR-16 | Обратная конвертация Word по паре «деперсонализированный .docx + ключ» | Must | Полный цикл «прямая → обратная конвертация» возвращает все исходные значения (текст документа совпадает по содержимому) |
| FR-17 | Валидация выбора для Word: минимум одна категория или одно дополнительное значение | Must | Без выбора выводится понятная ошибка, конвертация не запускается |
| FR-18 | Деперсонализация .docx категорий «Адреса», «Паспортные данные», «Названия компаний», «Реквизиты организации», «Банковские реквизиты» встроенными правилами | Must | Значения заменяются на индексы `ИДАДРЕС_`, `ИДПАСП_`, `ИДКОМП_`, `ИДРЕКВ_`, `ИДБАНК_`; документ остаётся корректным .docx |
| FR-19 | Связанные диапазоны: паспорт «серия + номер», «код подразделения»; реквизиты с подписью (ИНН/КПП/ОГРН/БИК/р·с/к·с) | Must | Маскируется весь диапазон с подписью; одиночные значения без подписи не заменяются произвольно |
| FR-20 | Фиксированный порядок замены категорий (телефоны → email → паспорт → реквизиты → банк → адреса → компании → ФИО) | Must | Токены одних категорий не попадают внутрь значений других; ключ хранит полные исходные значения |
| FR-21 | Телефон не распознаётся внутри более длинного числового ряда (счёт, ИНН) | Must | Слитный ряд маскируется своей категорией целиком; фрагмент, похожий на телефон, не заменяется отдельно |

## 8. Поля и данные

### Формат индекса

| Поле | Тип/варианты | Обязательное | Валидация | Использование |
|---|---|---|---:|---|---|
| Номер колонки `N` | целое, 1–99 | да | соответствует номеру выбранной колонки слева направо | префикс индекса `ИД<N>_` |
| Порядковый номер | целое, от 1, с ведущими нулями до 4 знаков | да | уникальность в пределах колонки | суффикс индекса `_<NNNN>` |

Индексы Word-категорий: префикс по категории (`ИДТЕЛ_`, `ИДЕМЕЙЛ_`, `ИДФИО_`, `ИДАДРЕС_`, `ИДПАСП_`, `ИДКОМП_`, `ИДРЕКВ_`, `ИДБАНК_`, `ИДДОП_`) + порядковый номер `_<NNNN>`; порядковый номер уникален в пределах категории.

### Ключевая таблица-словарь

| Поле | Тип/варианты | Обязательное | Валидация | Использование |
|---|---|---|---:|---|---|
| Исходная_колонка | текст (заголовок колонки исходного листа) | да | совпадает с заголовками исходного файла | связь индекса с колонкой |
| Индекс | текст формата `ИД<N>_<NNNN>` | да | уникален в пределах колонки | замена при обратной конвертации |
| Исходное_значение | текст/число | да | не пустое | восстановление значения |

### Выходные файлы

| Файл | Тип | Назначение |
|---|---|---|
| `*_деперсонализированные.xlsx` | xlsx | таблица с индексами вместо значений в выбранных колонках; остальные колонки и строка заголовков без изменений |
| `*_ключ.xlsx` | xlsx | словарь соответствий «индекс → исходное значение» |
| `*_восстановлено.xlsx` | xlsx | результат обратной конвертации, совпадает с исходным файлом |

## 9. Бизнес-правила

| ID | Условие | Результат | Объяснение пользователю/менеджеру |
|---|---|---|---|
| BR-01 | Ячейка в выбранной колонке пустая | Значение не заменяется, в ключ не попадает | Пустые данные не являются персональными и не индексируются |
| BR-02 | Одно и то же значение встречается несколько раз в одной колонке | Получает один индекс | Сохраняется связность данных и компактность ключа |
| BR-03 | Обратная конвертация без файла ключа | Операция блокируется с ошибкой | Без словаря восстановить исходные значения невозможно |
| BR-04 | Путь выходного файла уже занят | Приложение запрашивает подтверждение перезаписи через диалог «Сохранить как» | Исключается случайная потеря существующего файла |
| BR-05 | Повторный выбор колонок перед конвертацией | Показывается сводка на подтверждение | Пользователь контролирует, какие данные уходят в ключ |
| BR-06 | Прямая конвертация одного и того же файла дважды | Индексы могут отличаться, ключ каждый раз описывает фактическую замену | Каждая операция независима; корректность гарантирует пара «файл + свой ключ» |
| BR-07 | В .docx значение встречается, но категория не выбрана | Значение не заменяется | Заменяются только выбранные категории и введённые пользовательские значения |
| BR-08 | Пользовательское значение совпадает с данными, которые распознаёт выбранная категория | Замена выполняется в порядке: сначала пользовательские значения (ИДДОП), затем категории | Правила детерминированы; каждое уникальное значение получает один индекс |
| BR-09 | Обратная конвертация Word с отсутствующим или несовместимым ключом | Операция блокируется с ошибкой и понятным объяснением | Без корректного словаря восстановить исходные значения невозможно |
| BR-10 | Длинный числовой ряд (банковский счёт, ИНН) содержит фрагмент, похожий на телефон | Фрагмент не заменяется; ряд маскируется своей категорией целиком | Исключается порча длинных реквизитов и появление «полу-токенов» |
| BR-11 | Значение одной категории входит в значение другой (ФИО внутри названия компании, адрес с индексом/регионом) | Замена по фиксированному порядку из FR-20; значение маскируется полностью по исходному тексту | Обе категории получают корректные индексы, полный цикл точный |

## 10. Состояния интерфейса

- начальное (главное окно с выбором сценария);
- выбор исходного файла;
- выбор колонок;
- сводка и подтверждение;
- запрос пути сохранения (прямая конвертация: выходной файл, затем ключ);
- выполнение конвертации (индикатор выполнения);
- успешное завершение с путями сохранённых файлов;
- ошибка (неверный формат, отсутствие колонок, несовместимый ключ, недоступный путь);
- обратная конвертация: выбор файла и ключа, запрос пути, завершение.

## 11. Нефункциональные требования

- Стек: Python 3.10+, графический интерфейс `tkinter`, работа с xlsx через `openpyxl`, с .docx через `python-docx`.
- Поддерживаемая ОС: Windows 10/11 (основная); tkinter обеспечивает потенциальную совместимость с macOS/Linux.
- Интерфейс на русском языке; все сообщения об ошибках понятны и содержат инструкцию к действию.
- Конфиденциальность: приложение не выполняет ни одного сетевого запроса, не содержит ключей/токенов, не собирает телеметрию; вся обработка в оперативной памяти.
- Отсутствие внешних зависимостей времени выполнения: не используются нейросети, ML-библиотеки и облачные API.
- Производительность: обработка файла до 100 000 строк без блокировки интерфейса (замена выполняется поблочно, окно показывает прогресс).
- Структура поставки: `main.py`, `requirements.txt` (openpyxl, python-docx), `README.md`; приложение запускается командой `python main.py`.
- Фиксированный формат входных данных: xlsx, первый лист, заголовки в первой строке.

## 12. Критерии приемки Given / When / Then

### AC-01 — прямая конвертация сохраняет оба файла

- **Given:** тестовый файл `test.xlsx` с колонками «ФИО», «Телефон», «Регион», всего 1 000 строк, отмечены колонки «ФИО» и «Телефон»
- **When:** пользователь запускает прямую конвертацию и указывает пути сохранения
- **Then:** создаются `test_деперсонализированные.xlsx` и `test_ключ.xlsx`; в выбранных колонках только индексы `ИД1_0001`, `ИД2_0001` и т.д., колонка «Регион» и заголовки не изменены

### AC-02 — одинаковые значения → один индекс

- **Given:** в колонке «Телефон» значение повторяется 50 раз
- **When:** выполняется прямая конвертация
- **Then:** все 50 строк содержат один и тот же индекс, в ключе ему соответствует одно Исходное_значение

### AC-03 — обратная конвертация восстанавливает данные

- **Given:** пара файлов из AC-01
- **When:** запускается обратная конвертация и указывается путь сохранения
- **Then:** создаётся `test_восстановлено.xlsx`, совпадающий с `test.xlsx` по всем ячейкам первой строки заголовков и данных

### AC-04 — задаётся путь сохранения

- **Given:** пользователь выполнил сводку и нажал подтверждение
- **When:** начинается сохранение
- **Then:** открывается стандартный диалог «Сохранить как»; результат не записывается, пока путь не выбран

### AC-05 — пустые ячейки не индексируются

- **Given:** в выбранной колонке есть пустые ячейки
- **When:** выполняется прямая конвертация
- **Then:** пустые ячейки остаются пустыми и отсутствуют в ключе

### AC-06 — ошибка при отсутствии колонок

- **Given:** пользователь не отметил ни одной колонки
- **When:** нажимает «Деперсонализировать»
- **Then:** выводится сообщение «Отметьте хотя бы одну колонку», конвертация не запускается

### AC-07 — ошибка обратной конвертации без ключа

- **Given:** пользователь выбрал только деперсонализированный файл
- **When:** запускается обратная конвертация
- **Then:** выводится сообщение «Не выбран файл ключа», восстановление не выполняется

### AC-08 — исходный файл не изменяется

- **Given:** исходный `test.xlsx`
- **When:** выполняется прямая и обратная конвертация
- **Then:** контрольная сумма `test.xlsx` до и после операций совпадает

### AC-09 — прямая конвертация Word заменяет данные и сохраняет ключ

- **Given:** тестовый `test.docx` содержит телефон `+7 900 123-45-67`, email `ivanov@mail.ru`, ФИО «Иванов Иван Иванович», а также телефон в ячейке таблицы; выбраны категории «Телефоны», «Email», «ФИО»
- **When:** пользователь запускает «Прямую конвертацию (Word)» и указывает пути сохранения
- **Then:** создаются `test_деперсонализированные.docx` и `test_ключ.docx.xlsx`; в тексте документа нет исходных телефона/email/ФИО, вместо них присутствуют токены `ИДТЕЛ_0001`, `ИДЕМЕЙЛ_0001`, `ИДФИО_0001`; документ открывается без ошибок

### AC-10 — одинаковые значения в Word → один индекс

- **Given:** в `test.docx` телефон `+7 900 123-45-67` повторён дважды (в тексте и в таблице)
- **When:** выполняется прямая конвертация Word
- **Then:** оба вхождения заменены на один индекс `ИДТЕЛ_0001`, в ключе ему соответствует одно Исходное_значение

### AC-11 — обратная конвертация Word восстанавливает данные

- **Given:** пара «деперсонализированный .docx + ключ» из AC-09/AC-10
- **When:** запускается «Обратная конвертация (Word)» и указывается путь сохранения
- **Then:** создаётся `test_восстановлено.docx`, извлечённый текст которого совпадает с текстом исходного `test.docx` (полный цикл прямой → обратной конвертации)

### AC-12 — ошибка Word при отсутствии выбора

- **Given:** пользователь открыл «Прямую конвертацию (Word)», но не отметил ни одной категории и не ввёл значений
- **When:** нажимает «Деперсонализировать»
- **Then:** выводится сообщение «Отметьте хотя бы одну категорию или введите свои значения», конвертация не запускается

### AC-13 — адрес маскируется целиком

- **Given:** в `test.docx` строка «Юридический адрес: 428000, Чувашская Республика, г. Чебоксары, пр-т Мира, д. 19, офис 305.» и второй адрес «г. Москва, ул. Тверская, д. 1, стр. 2.»; выбрана категория «Адреса»
- **When:** выполняется прямая конвертация Word
- **Then:** оба адреса маскируются целиком, включая почтовый индекс и регион; в тексте отсутствуют «428000», «Чувашская Республика», «Чебоксары», «Москва»; вместо них токены `ИДАДРЕС_0001`, `ИДАДРЕС_0002`

### AC-14 — реквизиты и банковские реквизиты маскируются

- **Given:** в `test.docx` есть «ИНН 7707083893, КПП 770701001», «ОГРН 1027700132195» и «р/с 40702810900000001234, БИК 044525225, к/с 30101810400000000225»; выбраны категории «Реквизиты организации» и «Банковские реквизиты»
- **When:** выполняется прямая конвертация Word
- **Then:** все номера заменены токенами `ИДРЕКВ_…` и `ИДБАНК_…`; ни один номер исходно не присутствует в тексте

### AC-15 — телефон не «поедает» длинный счёт

- **Given:** в `test.docx` есть счёт «р/с 40702810900000001234» и телефон «8 900 123 45 67»; выбраны «Телефоны» и «Банковские реквизиты»
- **When:** выполняется прямая конвертация Word
- **Then:** фрагмент «81090000000» внутри счёта НЕ заменяется как телефон; счёт маскируется целиком токеном `ИДБАНК_…`

### AC-16 — паспортные данные маскируются

- **Given:** в `test.docx` есть «Паспорт: серия 45 12 № 345678»; выбрана категория «Паспортные данные»
- **When:** выполняется прямая конвертация Word
- **Then:** серия и номер заменены токеном `ИДПАСП_0001`; при этом слитное число ИНН (например, «7707083893») паспортной категорией не затрагивается

## 13. Ограничения и допущения

- Обрабатывается только первый лист xlsx; книги с нужными данными не на первом листе требуют подготовки файла пользователем.
- Заголовки колонок находятся в первой строке; иначе колонки нумеруются автоматически.
- Формат значений (текст/число/дата) в выбранных колонках может приводиться к текстовому виду в ключе.
- Ключ хранится без шифрования; защита ключа — ответственность пользователя.
- Индексы при повторной конвертации не детерминированы относительно предыдущего прогона.

## 14. Риски и открытые вопросы

| Риск/вопрос | Влияние | Решение для MVP |
|---|---|---|
| Потеря или утечка файла ключа | Невозможность восстановить данные | Явное предупреждение пользователю хранить ключ отдельно; проверка наличия ключа при обратной конвертации |
| Большой файл замедляет интерфейс | Долгое ожидание при 100 000+ строк | Поблочная обработка с индикатором прогресса |
| Дата/числовые форматы в ключе | Число 100 и текст «100» различимы при восстановлении | Хранение значения в исходном виде и сравнение с учётом типа ячейки при обратной конвертации |
| Открытый вопрос: нужно ли шифрование ключа паролем | Следующая итерация | В MVP не входит, зафиксировано в границах |
| Открытый вопрос: поддержка csv и многостраничных книг | Следующая итерация | В MVP не входит, зафиксировано в границах |

## 15. План проверки пилота

Тестирует сам пользователь на следующем наборе сценариев с метриками:

- Сеть: файл `test.xlsx` (1 000 строк, колонки «ФИО», «Телефон», «Регион», 50 дублей телефона, 10 пустых ячеек). Метрики: AC-01, AC-02, AC-04, AC-05, AC-06, AC-08.
